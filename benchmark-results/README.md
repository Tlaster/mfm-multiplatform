# MFM Parser 直接 AST 迁移基准报告

## 对比对象

- 基线：`Tokenizer -> TreeBuilder -> normalizeCompat`，源码基线为 `e52d1dbee925f56e9c6b15ad9b22694c1bcbffa8`。
- 新实现：单次扫描原始 `String`，通过显式 frame 栈直接构造公开 AST。
- 公共入口保持为 `MFMParser(emojiOnly).parse(text): RootNode`，公开节点类型未改动。
- 生产解析实现从 2,881 行降为 1,134 行（-60.6%）；旧内部实现已完全删除。
- 一次 `parseBatchOf1000Posts` 操作代表顺序解析 1,000 条消息；其他场景一次操作代表解析一条输入。

## 测试环境与方法

- 机器：Apple M1 Ultra，20 核，128 GB RAM
- 系统：macOS 27.0（26A5406e）
- JVM：Amazon Corretto 21.0.6
- JMH：1.37，经 `kotlinx-benchmark` 0.4.17 生成
- 模式：Throughput，1 thread，1 fork
- 堆：`-Xms512m -Xmx512m`
- 预热：3 × 1 s；采样：5 × 1 s
- 分配量：JMH `-prof gc` 的 `gc.alloc.rate.norm`（B/op）

两版都使用同一条命令：

```shell
java -Xms512m -Xmx512m \
  -jar build/benchmarks/jvmBenchmark/jars/mfm-multiplatform-jvmBenchmark-jmh-0.2.8-SNAPSHOT-JMH.jar \
  -wi 3 -i 5 -w 1s -r 1s -f 1 -prof gc -rf json -rff <result.json>
```

JMH 的 `±` 是默认 99.9% 置信区间。原始、未取整数据见 [baseline.json](baseline.json) 和 [optimized.json](optimized.json)。

## 迁移验证

- JVM：94/94 tests 通过，其中 62 个旧 AST 断言已迁移为直接测试公开 `MFMParser`，另有 30 个上游兼容测试和 2 个压力回归测试。
- macOS Arm64 Native：同一组 94/94 tests 通过。
- WasmJS：生产代码与测试代码编译通过；其余声明的 Kotlin/Native target 编译通过。
- 发布 JAR 不包含旧 `Tokenizer`、`TreeBuilder` 或相关状态类。
- JVM POM 只包含 Kotlin stdlib；benchmark runtime 没有泄漏为库依赖。

## 结论

- 正常负载的吞吐提升为 **9.498×–17.983×**；批量 1,000 条消息从 **111.20 ms** 降到 **11.71 ms**。
- 正常富文本负载的分配量降低 **92.89%–94.20%**；1 MiB 纯文本从约 **40.97 MB/op** 降到 **362 B/op**。
- 旧实现在连续无匹配闭合符上呈近似二次增长：输入从 4 KiB 增至 32 KiB（8×），耗时增至约 75.5×。新实现相同区间耗时约 7.9×，保持线性。
- 新实现用显式 frame 栈处理嵌套；额外回归测试覆盖 2,000 层嵌套，不依赖 JVM 调用栈。

这些数字是单线程解析内核的对比，用来排除调度器、线程池和业务 I/O 的干扰；它们不等同于端到端服务 QPS。

iOS Simulator / Kotlin/Native 的同场景结果见 [IOS_SIMULATOR.md](IOS_SIMULATOR.md)。
